# Breezy

- Never open breezy.k5d.de in a copy of my Firefox profile: edits sync to the shared board my partner sees, and Playwright's `setOffline` doesn't reach its container tabs. Test against localhost (`npm run dev`).
- Small PRs off main, no stacks, merged only when every job is green, none merged red: a red job left standing hides the next failure. A fix a later PR carries goes into its own PR off main first; the older PRs are then rebased onto main (`--force-with-lease` is allowed on them) and must go green themselves. Only Main runs on a pull request; to try a branch on real devices, `gh workflow run nightly.yaml --ref <branch> --field only=<desktop|android|ios|measures>` (never `all` while PRs are open: a whole night's macOS jobs keep the gate's waiting); failures are in `build/scenarios/*/timeline.txt`, `case.json` and each device's `flight.json`, what its app recorded (`web/flight.ts`), and a failing hub case's in `build/hub/`.
- A bug found by hand, or by a nightly run, is debugged through `.claude/skills/debugging-breezy`, from its recordings, before its code is read; it is fixed with a test at the lowest level that shows it, the fake taught when it was wrong, and a row in `docs/escapes.md`; `TESTING.md` says which level owns which class of bug.
- Bound every wait: a background run gets a hard deadline sized to its expected time and a check-in then; test files exit on their own, with a whole-file deadline; CI jobs carry `timeout-minutes`. An Android loop once sat an hour after passing, `node --test` held open by Firefox on Android's connection.
